Forge Companion 1.0.63 makes HealthKit workout backfill resume from Forge's
actual backend state.

The backend now returns the workout external IDs that already have complete
summary, time-series, and route evidence. The iOS app seeds its historical
workout progress from that backend count, so a phone with 1,000 workouts and
800 already stored in Forge starts at 800/1,000 with 200 left, not 0/1,000.

Already-uploaded decisions no longer depend on a local iOS completed-workout
checkpoint. Forge only marks a workout skippable when the backend has the
expected evidence rows, and incomplete summary-only imports are retried.

Historical workout batches are now mapped with a bounded prefetch queue, so
HealthKit evidence gathering can run ahead while uploads preserve deterministic
chunk order.

Background upload sessions now use the backend-workout-state chunking version
and allow two concurrent background connections to reduce stalls without losing
ordered resume semantics.

This TestFlight build keeps beta review submission disabled while CI uploads the
IPA, waits for processing, and attaches this changelog.
